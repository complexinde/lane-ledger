# LaneLedger design

AI-assisted original local prototype; no deployment, publication, hosting, users, rewards or live wallet business-flow claims. Synthetic inputs contain no PII. Constructor has zero arguments. Each unique record ID permanently binds owner, chain, contract, source URLs/byte hashes and policy. OPEN→DERIVED→CONFIRMED, owner can REVOKE terminally from any stage; expectedRevision and exact certificate ID required for confirm. Permissionless one-time derive; source refetched/hash/schema/full result recomputed by leader and every validator during open/derive/confirm. No LLM. Offline revoke is allowed. Each record has at most four history entries. Sources use canonical HTTPS raw.githubusercontent.com owner/repo/40-lowercase-hex/path; every segment rejects dot/empty and no query/fragment/encoding. UTF8 strict JSON rejects duplicates/nonfinite/unknown fields; exact SHA and response200 required, <=16384 bytes each. Bounds are checked after transport, not network bandwidth/redirect controls. No source publisher identity proof.

Frontend: original domain-specific local preview and manual explanation plus MetaMask61999 open→derive→ownerconfirm/revoke, actual decoded dict reads, fullTransaction finalized observation and mandatory independently unformatted raw exact hash/from/to/value0/NORMAL/majority/uniqueleaderSUCCESS proof. Check every provided SDK identity/finality/execution field; missing Studio fields never synthesized. Before broadcast persist public original sender/target/record/method/hash-null context; only explicit4001 rejection clears hashless attempt. Unknown status survives same-tab reload and blocks replay; exact wallet activity hash can attach for observation only. Busy freezes all controls; captured address/record epoch rejects stale reads and callbacks. No keys or private reveal data. Public URLs/deployment/hosting/live remain null; browser visual QA not performed.

## Minimum lanes and independent lower bound
Source exactly {version:1,events:[{id,start,end}]} with0..16 unique ASCII IDs matching [A-Za-z][A-Za-z0-9_]{0,23}; exact integer0<=start<end<=1000000, bool rejected. Intervals are half-open [start,end). Canonical order=(start,end,id). At each interval release lanes whose prior end<=start and choose the lowest free lane, else append the next contiguous lane ID starting0.

Independently sweep sorted unique endpoints; at each tick active IDs satisfy start<=tick<end, so end events precede starts. Keep the earliest tick with strict new maximum and ASCII-sorted active IDs. Full result includes ordered assignments, per-lane IDs, lane_count, lower-bound overlap tick/IDs/count; lane_count must equal maximum overlap. Empty source is EMPTY with lane_count0, null witness tick and no IDs. Nonempty is SCHEDULED. No allocation is an actual booking/attendance/external work promise; coordinates/ticks are abstract.

API: open_program(record_id,source_url,source_sha256); derive_program(record_id,expected_revision); confirm_program(record_id,expected_revision,certificate_id); revoke_program(record_id,expected_revision,reason); get_program(record_id); get_configuration(). All views return decoded dictionaries. Open creator is record owner.

UI: original interval table editor/export, lane timeline, selectable integer instant and exact active-overlap list, maximum-overlap bound/witness panel; chain overlay verifies the complete deterministic lane assignment. Tests cover equal endpoint release, simultaneous starts/end tie order, lowest lane reuse, nested intervals, earliest max witness, invalid zero length and empty.
